## 1. 产品定义

**跟着音乐敲准点、按对音，音乐永远好听。你只是加入它，而不是毁掉它。**

三个价值支柱：

| 支柱 | 玩家感知 | 机制承载 |
|---|---|---|
| 节奏感 | "我踩点越来越稳了" | 固定毫秒判定 + 偏差 σ（稳定度） |
| 音感 | "我听得出下一个音在哪" | 旋律家 5 列五声音高 + 辅助渐隐 |
| 解压 | "不用赢，也不会输" | 无失败、backing 不断、正向反馈 |

## 2. 目标用户与场景

| 场景 | 时长 | 需求 | 设计响应 |
|---|---|---|---|
| 睡前放松 | 3–5 分钟 | 不想动脑、不想挫败 | 55 秒一局、无失败、BPM 65–75 |
| 通勤碎片 | 1–2 分钟 | 随时开始随时停 | 秒开局、暂停无损、退出保留成绩 |
| 认真练习 | 10 分钟+ | 想看到进步 | 三维结算 + 偏差诊断 + 稳定度趋势 |

非目标：竞技、排行榜、社交、养成。v1 不做。

---

## 3. 核心循环

```
选模式 → 选曲 → 调难度 → [4 拍倒数] → 演奏 16 小节 → 三维结算 → 再来 / 返回
```

单局 16 小节，四段结构，55 秒左右。

## 4. 舞台与布局

### 4.1 屏幕分区

```
0%    ┌───────────────┐
      │  HUD 分数 / 连击 │
8%    ├───────────────┤
      │               │
      │    坠落区      │  ← 音符自 -60px 处生成，向下坠落
      │               │
78%   ├───────────────┤  ← 判定线（全宽，随拍脉动）
      │    击打区      │  ← 拇指自然落点
100%  └───────────────┘
```

| 常量 | 值 | 说明 |
|---|---|---|
| 判定线 | `0.78 × 屏高` | 给拇指留 22% 空间 |
| 生成线 | `-60px` | 屏幕外 |
| 预读时间 | 1.8s（可调 1.2–2.5s） | 定义"速度"，不直接用 px/s |
| 下落速度 | `(0.78H + 60) / 预读` | 812 屏约 385 px/s |
| 音符尺寸 | 36 × 18 px 胶囊 | 圆角 9 |

**纵向相对横向的红利**（竖屏 375×812）：

| | 横向（demo） | 纵向（v1） |
|---|---|---|
| 预读长度 | 292 px | 693 px |
| 8 分 @70BPM 间距 | 31 px | 155 px |
| 音符占位 | 28 px | 18 px |
| 结果 | 必然重叠 | 留白 8 倍 |

### 4.2 关于「音高轴」的修正（重要）

v0 草案写"旋律轨内高度 = 音高"。**在纵向下落中这是不可实现的**：y 轴已经被时间占用，音符的高度就是它到判定线的距离，无法同时表达音高。

因此音高必须走 **x 轴**：

> **MELODY 轨内部再分 5 列，横向位置 = 五声音阶的 5 个音高。**

这与钢琴类手游（Piano Tiles）的成熟解法一致，也是唯一能在纵向滚动里做空间化音高判定的方式。

## 5. 模式 A：鼓手（练节奏感）

4 轨纵向，单手双拇指即可上手。

| 轨 | 音色 | 谱面角色 | 颜色 |
|---|---|---|---|
| 1 KICK | 低音鼓 | 每小节第 1 拍，正拍骨架 | `#5B8CFF` |
| 2 SNARE | 军鼓 | 第 2、4 拍，回拍感 | `#FF7A59` |
| 3 CH | 闭镲 | 8 分填充，正反拍 | `#35D0BA` |
| 4 OH | 开镲 | 乐句末尾 / 段落切换 | `#C084FC` |

### 谱面密度

| 档位 | 每小节音符 | 内容 |
|---|---|---|
| 入门 | 4 | 全正拍，只练稳 |
| 熟练 | 8 | 加反拍 CH |
| 挑战 | 11–13 | 16 分加花 + 切分，每 2 小节一次 |

> 难度提升靠**密度与切分**，不靠加快 BPM。加快 BPM 会让"稳"的训练失效。

## 6. 模式 B：旋律家（练音感 + 双手）

**左侧 PAD 轨 + 右侧 MELODY 5 列，共一条判定线。**

```
┌────────┬────┬────┬────┬────┬────┐
│  PAD   │ C  │ D  │ E  │ G  │ A  │
│ 1.5 份 │ 1  │ 1  │ 1  │ 1  │ 1  │   ← 横向单位
│        │    │    │    │    │    │
│ 长按   │      点按，列 = 音高      │
│ 和声   │      五个音 = 当前调五声  │
├────────┴────┴────┴────┴────┴────┤   ← 判定线
│  按住  │        点击             │
└─────────────────────────────────┘
```

宽度分配：PAD 1.5 单位，5 个旋律列各 1 单位 → 375 屏下 PAD 88px、每列 58px。

### 6.1 PAD 轨（左）

- 长按（Hold），跨 1.75 小节，落在和弦根音。
- 按住渐入 120ms，松手渐出 200ms。
- 提前松手 → 按持续比例结算，**不判错、不断连击**（松手是"少弹"，不是"错"）。
- **默认开启**，设置里可关闭。关闭后 MELODY 占满全宽，变成纯旋律模式（新手友好）。
- 训练价值：和声感 + 持续稳定。

### 6.2 MELODY 区（右，5 列）

- 点按（Tap），列 = 音高，一个八度内的五声音阶。
- 各调音高表：

| 曲目调 | 五声音高（C 调记法） | MIDI |
|---|---|---|
| C | C D E G A | 72 74 76 79 81 |
| G | G A B D E | 67 69 71 74 76 |
| D | D E F# A B | 74 76 78 81 83 |
| F | F G A C D | 65 67 69 72 74 |
| Am | A C D E G | 69 72 74 76 79 |

- **音高判定可开关（默认开）**：
  - 开：必须点中正确的列。点错列 → 该音符最高只能判 GOOD，并播放你点到的那一列的音（**柔性失败**：听着跑调，但不刺耳，因为仍在五声内）。
  - 关：旋律区任意位置点击都算命中最近音符 → 退化为纯节奏模式。
- 这个开关同时是**难度阀**和**体验对照实验**，用于验证"音高是否太难"。

### 6.3 辅助渐隐（音感教学设计）

| 阶段 | 显示 | 依赖 |
|---|---|---|
| L1 入门 | 列头显示音名 + 音符带音名 | 眼睛 |
| L2 熟练 | 列头显示音名，音符不带 | 眼 + 记忆 |
| L3 挑战 | 列头仅在最后 0.5s 高亮 | 耳朵 |

## 7. 模式 C：节奏（练时值）

> 目标不是"打准点"，而是**知道一个音该有多长、什么时候必须闭嘴**。
> 这是鼓手模式练不到、旋律家模式又会被音高干扰的那部分能力。

### 7.1 交互模型：小节格子 + 时值块

一条纵向卷帘、一条判定线、一个底部敲击区。**没有轨道分叉，没有音高**。屏幕上唯一的信息就是「时间」和「时值」。

#### 第一原则：每个小节是一个等高容器

**格子高度 = 小节时长 × 滚动速度，与里面塞了几个音完全无关。**
这是整个模式的视觉地基——只有格子等高，"小节"才能成为一个可数的单位。
（同一 BPM 段内严格等高；跨段时 BPM 变、格高随之变矮，见 7.7。）

```
┌──────────────────────┐
│ ┌──────────────────┐ │ ← 小节 1
│ │  ██████████████  │ │   全音符：一个块填满整格
│ └──────────────────┘ │
│ ┌──────────────────┐ │ ← 小节 2
│ │  ████████████    │ │   二分：上半格
│ │  ████████████    │ │   二分：下半格
│ └──────────────────┘ │
│ ┌──────────────────┐ │ ← 小节 3
│ │  ▒▒▒▒▒▒▒▒▒▒▒▒▒▒  │ │   二分休止
│ │  ████████████    │ │   二分
│ └──────────────────┘ │
├──────────────────────┤ 判定线
│      敲 击 区         │
└──────────────────────┘
```

三条配套规则，缺一条格子感就塌：

1. **块长按比例换算，不按绝对像素。** 块高度 = `时值 / 小节拍数 × 格子内高`，
   所以一小节里所有块加起来正好填满格子，不会溢出也不会留白。
2. **格子之间只断开 4px**，每个分界再补一条 1.5px 贯穿车道的小节线。
   缝隙小到 4px 时，"留白"本身已经说明不了分节 —— 容器与内容的层级差才是。
3. **层级分明**：卷帘底 → 格子底（**比卷帘底更暗**，成凹槽）→ 块（亮条）。
   格子用"更暗"而不是"更亮"来区分，块才会显得浮在槽里。
   块宽比格子窄 60px（左右各 30px 槽边），格子轮廓才露得出来。
4. **格子高度随 BPM 变。** 滚动速度（像素/秒）全程固定，BPM 升一档，
   同一小节占的秒数变少 → 格子自然变矮。加速这件事本身就看得见。

#### 谱面元素

| 谱面元素 | 视觉 | 操作 |
|---|---|---|
| 全音符（4 拍） | 一整块填满格子 | 点一下（挑战档按住 4 拍） |
| 二分音符（2 拍）×2 | 半格 + 半格，中间一条缝 | 各点一下 |
| 二分 + 二分休止 | 半格彩色 + 半格灰色斜线 | 敲前半，后半留白 |
| 附点二分（3 拍） | 占格子 3/4，标签 `3拍·` | 点一下（挑战档按住） |
| 附点四分（1.5 拍） | 占格子 3/8，标签 `1½拍·` | 点一下 |
| 三连音（2/3 拍 ×3） | 三条等长、换用副色 `--accent-b`、右上角标 `3` | 各点一下，均匀 |
| 延音线（连音） | 两个时值合并成一条，顶部有连音弧 | 点一次 |

**块的物理长度 = 时值**，但它始终是"格子里的比例"，不是绝对时长对应的像素。

### 7.2 判定

**时值判定（松手时长）只在挑战档打开。** 这是这一模式最重要的难度分层。

| 项 | 入门 / 熟练 | 挑战 |
|---|---|---|
| 起音 | 与鼓手同窗口（±40/75/120ms），只判落点 | 同左 |
| 长音符 | **不判松手**，起音即满分；按住只是视觉反馈 | 起音 60%，松手结算 40% × 按住比例 |
| 松手早 | 不记「时值不足」，无提示 | 记一次「时值不足」，**不扣分、不额外惩罚** |
| 休止内敲击 | 记为「抢拍」：断连击 + 低鸣 + 浮字「休止」，不扣分 | 同左 |
| 空击 | 只发轻音，不罚 | 同左 |

**为什么把时值判定挪到后面**：时值其实是两层能力叠在一起——**读谱**（这块有多长）和
**手部计时**（我到底按了多久）。初学时两层同时要求，玩家只知道"我错了"，却分不清
是没看懂谱还是手不稳，练习就退化成罚站。所以入门/熟练先把「读谱」练到不看标签也能读，
挑战档再叠加计时。

结算第三维也随之切换：入门/熟练看「完整度」（有没有漏），挑战档看「时值」（按够了没有）。

**为什么休止要罚**：休止符不是"没有内容"，是**主动的静默**。不罚就永远练不出来。

### 7.3 难度梯度

| 档位 | 生成规则 | 时值判定 | 休止 |
|---|---|---|---|
| 入门 | **每小节所有音时值完全一样**：整小节切成 N 份（全音符 / 2 个二分 / 3 个三连音 / 4 个四分 / 5 个五连 / 6 个六连）。**没有附点** | 关 | 数量 ≤ 音符数的一半（即 ≤ 格数/3，向下取整），且不连续 |
| 熟练 | 在等分铺底上**随机拆 1~2 处**，拆出来的时值从「有名字的时值」表里凑，于是自然出现附点（`¾+¼`）与其他时值，例如 `1个½ + 2个¼` | 关 | 概率 22%，不连续，最多占半小节 |
| 挑战 | 拆 2~3 处、允许三连拆；另有一半概率直接套一条**风格动机** | **开** | 概率 22%，不连续，最多占半小节 |

**为什么时值只能从表里取**：允许的时值是
`4 / 3 / 2 / 1.5 / 1 / 0.75 / 0.5 / 0.25` 拍。切分必须从这张表里凑，
不能按比例硬切——按 0.75 去切一个 1.5 会得到 1.125，再切一次是 0.44，
玩家根本没法从块长度上认出那是什么音符，标签也写不出来。

**为什么挑战档还要"往风格靠"**：随机生成 + 无加权 = 一锅噪声，练完记不住任何东西。
风格动机是"这条律动属于谁"的来源。

**每局随机生成**（种子 = 时间 + 随机数），不追求复现。这是"练习器"而非"打歌"：
练的是**读时值的反应**，背谱没有意义。

生成规则（保证音乐性）：
1. 每小节时值总和必须精确等于拍号（含休止）——生成后有一次硬补齐。
2. 小节第一拍不放休止（保住强拍）。
3. 不连续两个休止。
4. 块与块之间时间连续，不留缝也不重叠。
5. 休止有上限：入门档按「休止数 ≤ 音符数的一半」反解成 `≤ 格数/3`，一格两格的短小节
   因此完全不留白；另两档放到半小节为限，绝不出现整小节静音。

### 7.4 音色：搞怪 SFX

时值练习会很枯燥，所以**敲击音本身要好玩**。8 种程序化音效，全部合成、零素材：

| id | 名称 | 合成方式 |
|---|---|---|
| `wood` | 木鱼 | 正弦 430→300Hz + 高频噪声瞬态 |
| `bubble` | 泡泡 | 正弦 240→1150Hz 上滑 |
| `boing` | 弹簧 | 正弦 150→465Hz + 24→9Hz 颤音 |
| `meow` | 喵喵 | 锯齿 + 双带通共振峰 + 三段音高滑音 |
| `duck` | 嘎嘎 | 方波 + 34Hz 幅度调制 + 带通 |
| `type` | 打字机 | 噪声瞬态 + 1.5kHz 金属音 |
| `laser` | 激光 | 锯齿 1700→190Hz 下滑 |
| `clap` | 拍手 | 三次噪声爆发（间隔 11ms） |

关键细节：**音高按五声音阶阶梯轮换**（`TIMBRE_LADDER = [0,2,4,7,9,12,9,7,...]`），
所以连打会自然形成一小段旋律，而不是同一个音重复。这是"解压"和"音感"的交点。

### 7.5 视觉规格

| 元素 | 规格 |
|---|---|
| 车道 | `min(屏宽 - 32, 430)` 居中，深色卷帘底（alpha 0.58–0.84）。必须压得住 scene 背景——rock 场景的灯柱是接近白色的，0.4 的遮罩会让块整片消失 |
| 滚动速度 | **按小节定速**：`look = 小节时长 × 2.15 + 0.6`，一屏装下约 **2 个小节格子** |
| 小节格子 | 高 = `小节时长 × 速度 - 4`，圆角 9，底 `rgba(2,3,7,0.34)`（比卷帘底更暗），描边 0.21；当前小节底 0.50 / 描边 0.34 |
| 格子间隙 | **4px**。缝隙收到 4px 后，光靠留白已经分不出小节，所以每个分界补一条小节线（见下） |
| 小节线 | 1.5px 贯穿车道（左右各内缩 3px），落在两格之间那道缝的正中；静态 0.34 白，当前小节用主题色 0.62 |
| 拍刻度 | 格子左缘每拍一条 7px 小横线，首尾拍更亮，数得出这一小节几拍 |
| 小节号 | **格子内部右上角**，右对齐于块右侧槽边内（`x + w - 10`），9px/700；静态 0.46 白，当前小节主题色 0.92。最后一遍绘制，不被块盖住 |
| 音符块 | 宽 = 车道 - 60（左右各留 30px 槽边）。块比格子窄一圈，格子轮廓才看得出来，右侧槽边同时是小节号的位置 |
| 块间隙 | 6px，太小就糊成一条色带，"一格里有几个音"读不出来 |
| 块填充 | 主色 0.30 → 0.42 → 0.56 渐变 + 主色描边 0.62。**必须偏实心**：长音符如果顶部近乎透明，会被读成"一个空框"，长度就比不出来了。按住时整体再提一档（0.40 / 0.52 / 0.64） |
| 头部 | 块底 9px 实色条，是唯一必须一眼找到的东西 |
| 内部拍线 | 每拍一条 0.20 alpha 横线，多拍时值一眼数得出来 |
| 时值标签 | 贴头部显示，用乐谱分数写法：`4拍` / `3½拍` / `1⅓拍` / `⅘拍` / `⅔拍` / `½拍` / `¼拍`（`·` = 附点）。块太矮时不显示，避免糊 |
| 休止块 | 灰底 + 45° 斜线阴影 + 虚线边框 + 居中「休止 N」 |
| 底部敲击区 | 整条大圆角（高度 ≥ 72px），中心「敲 击」/「休 止」双态；副标题随档位切换（挑战档「长音符按住到尾巴」，其余「跟着拍子敲下去」） |
| 休止提示 | 判定线上有休止时，敲击区整体变灰并显示「这一段别敲」 |
| 顶部渐隐 | 卷帘顶 54px 渐隐，长音符从暗处浮出而不是被硬切断 |

> 滚动速度**不受「音符速度」设置影响**。这一模式的信息密度是"时值长度"，
> 用统一的预读时间会让长音符无法完整显示，也让人无法比较长短。

### 7.6 风格与 BPM

节奏模式**没有伴奏**——这一档要练的是自己的时值，任何和弦、贝斯、加花都会把注意力拉走。
所以首页的「曲目」在这里换成**「风格」**：风格只决定"用什么律动练"，不提供音乐。

| 风格 | 拍号 | 缺省 BPM | 重音轮廓 | 特征动机 |
|---|---|---|---|---|
| Straight | 4/4 | 84 | 强-弱-次强-弱 | `1 1 1 1` · `2 1 1` · `1.5 .5 1 1` |
| Swing | 4/4 | 96 | 1、3 重，2、4 反拍 | `1 1 1.5 .5` · `2 1 1` |
| Bossa Nova | 4/4 | 92 | 1 重，3 次重 | `1.5 1.5 1`（3+3+2）· `1 1.5 1 .5` |
| Math Rock | 7/8 | 120 | 1、4、6 | `1.5 1 1` · `1 1.5 1` · `.5 .5 .75 .75 1` |

**风格 → 拍号 → 场景是一套**。选风格同时换拍号、换背景、换主题色（Straight→慵懒房间、
Swing→音乐家的房间、Bossa→赛博朋克、Math Rock→Live 舞台），
所以"风格"是整套练习环境的切换，而不是一个下拉选项。

BPM 由玩家用 `−/+` 调（40–200，步长 2），风格只给缺省值和律动倾向。
节拍器按 `风格.accent` 打重音，底鼓只落在每小节第一拍——这就是这一模式全部的伴奏。

### 7.7 一局 = 48 小节，每 16 小节 +10 BPM

```
第 1 轮    小节 1–16   BPM = base
           小节 17–32  BPM = base + 10
           小节 33–48  BPM = base + 20
              ↓ 结算页
        「加快速度继续 · base+30」→ 第 2 轮从 base+30 起，再爬三档
```

- 演奏中 HUD 常驻显示 `84 BPM · 12/48`，速度抬升是看得见的。
- 滚动速度（像素/秒）全程固定，BPM 升高只会让格子变矮——不重新教手感，只加压。
- 结算页把「加快速度继续」放在主按钮位；「再来一次」降为次要，避免两个主按钮抢焦点。
- 退出重进不保留 BPM，回落到当前风格的缺省值。

## 8. 判定、计分与反馈

### 8.1 判定窗口（固定毫秒，不随 BPM 缩放）

| 档位 | PERFECT | GREAT | GOOD | 判定偏移默认 |
|---|---|---|---|---|
| 休闲 | ±55ms | ±100ms | ±150ms | 0 |
| 标准 | ±40ms | ±75ms | ±120ms | 0 |
| 严格 | ±25ms | ±50ms | ±90ms | 0 |

> 40ms ≈ 人类"同时"感知阈值的 2 倍，是商业节奏游戏通用基准。

### 8.2 计分

| 判定 | 基础分 | 连击 |
|---|---|---|
| PERFECT | 100 | +1 |
| GREAT | 70 | +1 |
| GOOD | 40 | +1 |
| MISS | 0 | 清零 |

- 连击加成：每 10 连击 +2%，上限 +20%。**只有加成，没有惩罚。**
- 空击（点到没有音符的位置）：播放音效，**不扣分不断连**。解压优先。
- Hold：按持续比例 × 头部判定的基础分。

### 8.3 三维结算（替代单一分数）

| 维度 | 算法 | 能力 |
|---|---|---|
| **准确率** | 加权得分 / 满分 | 打得准 |
| **稳定度** | `clamp(100 - σ(偏差ms) / 1.5, 0, 100)` | 打得稳 |
| **完整度** | `1 - miss / 总音符` | 有没有漏 |
| **时值**（仅节奏模式**挑战档**，替换完整度） | `1 - 时值不足 / 按住过的长音符` | 音按够了没有 |

> 节奏模式的入门/熟练档不判松手，所以第三维仍显示「完整度」——没有数据就不该编一个出来。

单次 PERFECT 是运气，σ 小才是节奏感。结算页给一句话诊断：

| 偏差均值 | 文案 |
|---|---|
| < −40ms | 你整体偏早 40ms，可以再等一下 |
| −40 ~ +40ms | 节奏很稳 |
| > +40ms | 你整体偏慢 35ms，试着提前一点 |

节奏模式另有两句追加诊断（与上表**并列叠加**，不覆盖）：有抢拍时提示「休止里有 N 次抢拍」，
时值不足占比高时提示「长音松手偏早」；入门/熟练档追加「这一档只判落点，去挑战档再练按满」。
休止符不计入分母——它没有击打点。

等级：准确率 ≥95 S / ≥88 A / ≥78 B / ≥65 C / 其余 D。

### 8.4 失败反馈

| 事件 | 表现 |
|---|---|
| MISS | 判定线一次灰色涟漪，音符淡出，**backing 继续** |
| 断连击 | 数字缩小淡出，无红闪、无震屏 |
| 错轨 | 该轨轻微亮一下，不扣分 |
| 抢拍（节奏模式） | 底噪低鸣 + 浮字「休止」+ 连击清零，**不扣分** |

### 8.5 Zone

连续 50 连击进入 Zone：背景转暖、判定线加粗、分数 ×1.2、粒子增多。
**用奖励制造高潮，而不是用惩罚制造紧张。**

## 9. 单局结构

三个模式**并列**，共用同一套单局骨架，只在「看点」上分叉：

| 模式 | 看什么 | 一局时长 | 谱面来源 |
|---|---|---|---|
| A 鼓手 | 4 条轨、落点 | ≈51s | 曲目绑定 |
| B 旋律家 | 5 列音高 + PAD 轨 | ≈51s | 曲目绑定 |
| C 节奏 | 单轨块的**长度** | 48 小节（随 BPM 变，约 1.3–2.1 分） | **风格生成器** |

16 小节，四段（4/4 @75BPM ≈ 51 秒）：

| 段 | 小节 | 内容 | 感受 |
|---|---|---|---|
| A 起 | 0–3 | 稀疏，只鼓 + 贝斯 | 进入状态 |
| B 承 | 4–7 | 加 PAD，密度提升 | 跟上 |
| C 转 | 8–11 | 加花 / 切分，情绪最高 | Zone |
| D 合 | 12–15 | 回稀疏，长音收束 | 松下来 |

结尾必须"落"，不能戛然而止。

> 模式 C 不用这条四段曲线。它的"情绪曲线"换成了 **BPM 阶梯**——48 小节切成
> 3 段，每段 16 小节，段间 +10 BPM（见 7.7）。提速本身就是叙事：起、承、转都靠
> 越来越挤的小节格子说，不需要再叠编曲层次。

## 10. 音频架构（sfx.ts + bgm/）

> 判定优先级：**好听 > 好维护**。
> 早期版本的"纯振荡器实时合成"有塑料感、无层次，是因为缺了录音室里的三件事：
> 真实音源、空间、以及把各声部揉在一起的胶水。本节逐条给出解决方案。

### 10.1 三层职责

| 层 | 内容 | 控制方 |
|---|---|---|
| L0 backing | 鼓 + 贝斯 + 和声 + PAD 伴奏 | 全自动，**永不停止** |
| L1 guide | 旋律参考音（新手可开） | 可关 |
| L2 player | 玩家击打音 | 玩家 |

**MISS 时只是不播放 L2，L0 继续 → 音乐不断。** 这是"解压"的技术前提。

节奏模式（模式 C）是例外：L0 退化为「节拍器 click + 轻微军鼓/底鼓衬底」，
因为这一模式的听觉焦点必须是玩家自己的敲击时值。它和伴奏之间只保留三处联系：

| 联系 | 是否保留 |
|---|---|
| BPM / 拍号 | 保留。谱面按拍网格生成，每个音的起点都是拍的整数倍或半倍，和节拍器同源 |
| 鼓组音色 | 保留。衬底鼓组取 `GROOVE[场景].kit`（cyber→techno / lofi→lofi（合成） / classic、rock→acoustic），换歌＝换"鼓房" |
| 和弦 / 贝斯 / GROOVE 加花 | **断开**。不加，否则听感会从"练时值"滑向"跟着玩" |

### 10.2 信号链

```
采样 / 合成音源
   → 乐器总线（增益 · 声像 · 低切 · 低通）
   → 干声 ─────────────────┐
   → 发送 → 卷积混响 ───────┤→ 胶水压缩 → 限幅 → 输出
                          └→ 磁带底噪
```

| 环节 | 参数 | 作用 |
|---|---|---|
| 胶水压缩 | threshold −16dB | 把鼓与和声"压"成一个整体，不各响各的 |
| 限幅 | threshold −4.5dB | 兜底防削波（实测 maxPeak 0.74，安全） |
| 侧链 `duck()` | 底鼓落下时压低 pad/keys/bass | 低频让位，鼓点才砸得出来 |

> 侧链必须用**固定基准值**做目标，不能读 `.gain.value`——
> 后者在压缩过程中持续变化，会导致总线音量逐次衰减（原型踩过这个坑）。

### 10.3 空间：程序化卷积混响

混响不是装饰，是**距离感**。用噪声衰减 + 早期反射生成冲激响应（IR），按场景缓存，零素材成本。

| 预设 | 混响时长 | 衰减 | 高频阻尼 | 预延迟 | 湿度 | 附加 |
|---|---|---|---|---|---|---|
| `cyber` | 3.1s | 2.9 | 0.60 | 12ms | 0.30 | 8分音符延迟 0.245s |
| `classic` | 2.5s | 2.3 | 0.38 | 28ms | 0.42 | 大厅感，湿声最重 |
| `lofi` | 1.4s | 3.1 | 0.20 | 8ms | 0.26 | 磁带底噪 0.032 |
| `rock` | 2.9s | 2.0 | 0.52 | 34ms | 0.34 | 短促紧实，房间感 |
| `practice` | 1.6s | 2.6 | 0.34 | 10ms | 0.24 | 节奏模式专用，干声为主 |

**为什么每个场景要一套空间**：同一套混响套在赛博合成器和木吉他上，
前者糊、后者干。空间必须跟乐器材质一起换。

### 10.4 乐器与音色

| 乐器 | 实现 | 说明 |
|---|---|---|
| `piano` | 8 锚点采样 + 移调 | C3–C6（midi 48–84），最大移调 ±3.5 半音，超出才滑音可闻 |
| `rhodes` | FM 合成 | 载波 + 调制器 + 音叉高频 + LFO 颤音 |
| `lead` | 三层失谐锯齿 + 次低音 + 滤波包络 + 延迟发送 | 赛博主音 |
| `guitar` | Karplus-Strong 物理建模 + 过载 + 箱体低通 | 按音高缓存 buffer |
| `bass` | KS 拨弦 + 正弦超低音 | 保证小喇叭也有基频 |
| `pad` | 多层锯齿/三角 + 合唱调制延迟 | 铺底，混响发送 0.62 最湿 |
| `chipLead` / `chipBass` | 方波（+ 轻五度） / 三角波 | 8bit 专用，只给像素心跳 |
| `drum` | 3 套采样：`acoustic` / `techno` / `kpr77`；2 套全合成：`chip` / `lofi` | kick / snare / hihat / tom1 |

`lofi` 套鼓是算出来的，没有采样文件：军鼓 = 双模态鼓皮（1 : 1.58）+ 三段响弦噪声，4–8 ms 起音；底鼓 = 正弦扫频 + 12 ms 敲门噪声；踩镲 = 两层粉噪 + 一层 3.4 kHz 镲身。两套预设（`bright` / `tape`）每首曲子随机一套，只改音色不改电平。详见 `docs/research/lofi-drums.md`。

力度（velocity）会同时影响音量与**低通截止**——轻敲不只是小声，是更闷。
这是"真实感"最廉价也最有效的来源，纯合成做不到。

**背景音乐另有一套采样乐器**（不走 `sfx.ts` 的总线，见 12.1）：电贝斯、失真电吉他、
尼龙弦吉他、小提琴、大提琴、长笛、钢琴。每件只留 6–9 个音，播放时取最近的一个
做 ±3 半音内的变速 —— 再远就会听出"磁带跑调"。

### 10.5 程序化 SFX

9 种，全部合成、零素材，服务于节奏模式的音色切换与反馈（详见 7.4）：
`wood` 木鱼 · `bubble` 泡泡 · `boing` 弹簧 · `meow` 喵喵 · `duck` 嘎嘎 ·
`type` 打字机 · `laser` 激光 · `clap` 拍手 · `buzz` 抢拍低鸣。

### 10.6 编曲层（backing.ts）

按场景定义 `GROOVE`，在 16 分网格上生成鼓、贝斯、和声、加花事件，
0.4s lookahead + 25ms tick 定时调度。四个场景事件数：cyber 463 / classic 233 / lofi 251 / rock 443。

**鼓与和声是"生成"的，不是"写成谱"的**——同一 GROOVE 每局会有细微差别，听着不重复。
有固定编曲的曲目（像素心跳）例外：伴奏直接读 BGM 的结构谱（贝斯 + 琶音 + 鼓），
玩家打的旋律本身就是听到的旋律，漏音时另外三层还在，音乐不会散。

### 10.7 素材来源与体积

| 资源 | 来源 | 体积 |
|---|---|---|
| 钢琴 8 采样（对局） | Tone.js 官方音频库 | 224KB（单声道 64kbps，3.2s 带淡出） |
| 鼓组 3 套 × 4 件 | Tone.js audio / `nbrosowsky/tonejs-instruments` | 88KB |
| 六件真实乐器 47 采样（BGM） | `tonejs-instruments`（CC0：VSCO2 CE / Iowa / Karoryfer） | 1.1MB（单声道 44.1kHz 96kbps） |
| 合计 | 全部无版权，可商用；**全部本地**，不引用 CDN | **1.42MB** |

采样统一用 ffmpeg 转码成 `-ac 1 -ar 44100 -b:a 96k`，并按 `atrim + afade` 只留有用的那一段。
进 precache 的只有应用外壳；采样走运行时 `CacheFirst`，第一次播到哪首才下哪首。

### 10.8 小程序移植约束

**只用 WebAudio 1.0 标准节点，不依赖 AudioWorklet。** 全部节点均已确认在
微信 `WebAudioContext` 中存在：`ConvolverNode` / `DynamicsCompressorNode` /
`StereoPannerNode` / `BiquadFilterNode` / `WaveShaperNode` / `DelayNode`。

降级路径：
- `ConvolverNode` 不可用 → 退化为 4 级串联 `DelayNode` + 反馈的算法混响（Schroeder），保留湿度/衰减参数。
- 采样总 1.42MB，可随包体发布，**不需要预渲染 60s mp3**（早期方案里的 950KB backing 已被生成式编曲取代）。
  小程序的包体上限吃紧时，BGM 那 1.1MB 可以按曲目分包。
- 采样解码为 `Int16Array` 后缓存，切换曲目不重复解码。

## 11. 难度与设置项

只暴露一个"难度"档位，内部联动（三个模式各有独立文案与谱面池，见 7.3、8）：

| 档位 | 谱面密度 | 判定窗口 | 音高辅助 |
|---|---|---|---|
| 入门 | 4/小节 | ±55/100/150 | 音名全显 |
| 熟练 | 8/小节 | ±40/75/120 | 仅列头音名 |
| 挑战 | 11–13/小节 | ±25/50/90 | 最后 0.5s 显形 |

设置面板（原型必须实现）：

| 项 | 范围 | 默认 | 作用 | 适用模式 |
|---|---|---|---|---|
| 音符速度 | 1.2–2.5s 预读 | 1.8s | 手感核心参数 | 鼓手 / 旋律家 |
| 判定偏移 | ±150ms | 0 | 手动机型校准 | 全部 |
| PAD 轨 | 开 / 关 | **开** | 关掉只剩旋律 | 旋律家 |
| 音高判定 | 开 / 关 | 开 | A/B 验证难度 | 旋律家 |
| 音色 | 8 种搞怪音效 | `wood` | 敲击音本身要好玩的 | 节奏 |
| 风格 | 4 种（见 7.6） | `straight` | 同时决定拍号、缺省 BPM、场景 | 节奏 |
| BPM | 40–200（步长 2） | 风格缺省值 | 一局的起始速度 | 节奏 |
| 音效 | 开 / 关 | 开 | 击打音与伴奏 | 全部 |
| 背景音乐 | 开 / 关 | 开 | 首页与结算循环当前曲目，演奏时自动静音（见 12.1） | 全部 |

> 「风格」与「曲目」在首页是**同一个位置互斥替换**：节奏模式显示风格卡 + BPM 步进器，
> 另两个显示曲目列表。这样首页不会长出一个越来越长的设置区。

> 节奏模式**不受「音符速度」影响**：滚动速度按小节时长定额（见 7.5），
> 否则长音符无法完整显示，也无法比较长短。选中节奏模式时该行置灰。

| 曲目 | 场景 | 调 · 拍号 · BPM | 训练目标 |
|---|---|---|---|
| 像素心跳 | `pixel` | Am 4/4 132 | 固定谱面：听到的旋律就是打出来的旋律（默认曲目） |
| 霓虹脉冲 | `cyber` | C 4/4 84 | 正拍稳定（入门必修） |
| 城市夜行 | `cyber` | G 4/4 96 | 反拍 / syncopation |
| 月下圆舞 | `classic` | F 3/4 72 | 三拍子重心 |
| 长呼吸 | `lofi` | Am 4/4 64 | Hold 长音 + 耐心 |
| 雨窗午后 | `lofi` | D 4/4 68 | 音高入门 |

> 节奏模式**不选曲目**，选风格（见 7.6）。曲目表只管鼓手与旋律家两个模式——
> 它们需要调性、和弦走向才能"像一首歌"；节奏模式只需要拍号和速度。
>

> 所以听到的每个音就是该打的音。另外六首的谱面由曲目的调性与和弦生成，
> 难度只改密度，不改音高。

### 12.1 背景音乐（BGM）

首页与结算页循环播放当前曲目的编曲；**演奏中与暂停时一律不响**（暂停还留着伴奏，
回来会接不上拍，反而像 bug）。设置里有独立开关，和对局音效互不影响。

七首各有编制，靠**编制**而不是音量区分，不是同一套音色换参数：

| 曲目 | 编制 | 特征 |
|---|---|---|
| 像素心跳 | 方波主音 + 三角波贝斯 + 合成鼓 | 唯一的芯片音色，干净硬起音 |
| 霓虹脉冲 | FM 钟 + 超锯齿垫 + 电贝斯 | synthwave，ping-pong 回声是空间感来源 |
| 城市夜行 | 切分拨弦 + 电钢 + 闷 sub | 音符落弱拍，"夜行"的摇摆 |
| 月下圆舞 | 小提琴 + 钢琴 + 大提琴 | 钢琴三重奏，蹦-恰-恰，**无鼓** |
| 长呼吸 | 软钢琴 + 梦幻垫 + 尼龙弦琶音 + 软贝斯 + 合成鼓 + 磁带 | lofi，大量留白、连奏低音、磁带噼啪 |
| 雨窗午后 | 软钢琴 + 梦幻垫 + 尼龙弦指弹 + 软贝斯 + 合成鼓 + 磁带 | 指弹民谣骨架，贝斯半音级进接下一个和弦 |
| 地下现场 | 失真电吉他 riff + 八分 power chord + 重鼓 | 摇滚，中频突出 |

三条硬规则：

1. **旋律手写，不生成。** 上一版按"和弦音 + 种子挑动机"生成，结果每首都是
   "每小节六个等距音"，听十秒就分不清是哪首。现在一小节一行、16 格（3/4 为 12 格）、
   `.` 是留白，改一首曲子只动那一行数据。长呼吸与雨窗午后的"那一行"已经换成
   `src/songs/*.abc` 里的一份谱 —— 同一个意思：改旋律只改谱（或那行数据），不碰引擎。
2. **听到的就是要打的。** 像素心跳的 BGM 与谱面读同一份旋律，改一个音两边一起变。
3. **音色用真采样，不用塑料合成。** 电贝斯 / 电吉他 / 尼龙弦 / 小提琴 / 大提琴 / 长笛 /
   钢琴全部是 CC0 真实采样，本地随包发布（见 10.7）。合成只留给芯片音、FM 钟和 sub。

BGM 与实际对局音频是**两套独立的音频上下文**：对局的限幅和侧链不会压到 BGM，
关掉音效也不会顺手掐掉背景音乐。代价是钢琴采样会被解码两次（224KB），可以接受。

## 13. 解压机制清单

1. 音乐永远不会被玩坏
2. 无血条、无 Game Over、无倒计时
3. BPM 65–75（接近静息心率上沿，生理上诱导放松）
4. 判定线随拍呼吸、场景光随拍脉冲、背景色温随和弦缓慢漂移（周期 ≥ 8s）
5. **命中点亮场景**（`uEnergy`）——看得见的即时回报，比飘分更有体感
6. 一局 55 秒，随时可退，退出保留成绩
7. 只有加分，没有扣分
8. 结尾必须"落"（长音收束）

## 14. 无尽练习模式（保留随机谱面）

固定谱面用于"打歌/比成绩"，随机谱面用于"练手感"。

| | 打歌模式 | 无尽练习 |
|---|---|---|
| 谱面 | 固定（seed 固定） | 每轮随机 |

## 15. 工程结构（真源声明）

> **`apps/pwa/` 是交互与视觉的唯一真源。**
> 小程序实现必须对齐：布局常量、颜色、动效曲线、判定数值、文案。
> 偏离前先改 PWA，再抄。
>
> `prototype/` 已冻结。它是 PWA 迁移前的单文件原型，只用于视觉对照与历史回溯，
> **不再接受功能改动**。

仓库是 pnpm workspace monorepo：

| 路径 | 职责 |
|---|---|
| `apps/pwa/src/engine/game.ts` | 逻辑：谱面生成、判定、渲染、场景驱动、快照广播 |
| `apps/pwa/src/engine/sfx.ts` | 对局音频：混音台 / 卷积混响 / 采样 / 物理建模 / 程序化音效 |
| `apps/pwa/src/engine/backing.ts` | 编曲层：按 GROOVE 生成 L0 伴奏事件并调度；`buildRhythm()` 只出节拍器 + 首拍底鼓 |
| `apps/pwa/src/engine/bgm/` | 背景音乐：`compose`（手写编曲，剩五首）→ `score`（结构谱）→ `arrange`（排程）→ `voices`/`samples`/`drums`（发声）|
| `apps/pwa/src/engine/abc/` | ABC 谱引擎：`parse`（子集解析）→ `style`（风格预设 + `%%OB`）→ `toScore`（谱 → 结构谱）|
| `apps/pwa/src/engine/tape.ts` / `space.ts` | 磁带底噪（离线渲染的嘶声 + 噼啪）/ BGM 混响用的房间冲激响应（算出来的）|
| `apps/pwa/src/songs/` | 谱库：一首一个 `.abc`（当前长呼吸、雨窗午后）|
| `apps/pwa/src/engine/scene.ts` | 场景：WebGL 引擎 + 5 套 GLSL 氛围 |
| `apps/pwa/src/engine/index.ts` | 引擎门面：唯一的类型边界，导出快照类型与命令 |
| `apps/pwa/src/components/` | 界面：首页 / 演奏 HUD / 结算 / 设置 / 暂停 / 更新提示 |
| `apps/pwa/src/components/ui/` | shadcn 组件（源码在仓库里，按 spec-ui.md 的变体规则扩展） |
| `apps/pwa/src/index.css` | 令牌 → 语义层 → 工具类，Tailwind v4 CSS-first |
| `apps/pwa/public/assets/` | 采样 67 个 mp3 / 1.42MB：钢琴 8 + 鼓组 3 套 × 4 件 + 六件真实乐器 47 |
| `prototype/` | **冻结**：迁移前的单文件原型 |

引擎内部依赖单向：`game → {sfx, scene, backing}`，`backing → {sfx, bgm/score}`，
`bgm/` 自成一体。**没有挂在 `window` 上的 IIFE**，也没有循环依赖，
改哪一层都能只跑 `tsc` 验证。

顶部 `CFG` 对象集中所有可调数值，改玩法不改逻辑（`game.ts`）。
`game.ts` 与音频之间只隔一层 `AudioEng` 适配器——
小程序阶段把 `AudioEng` 换成 `WebAudioContext` 实现即可，玩法代码零改动。

**引擎与界面只通过快照通信。** 引擎不认识 React：
状态变化时 `emit()` 出一个新快照对象，界面用 `useSyncExternalStore` 订阅；
界面只调命令（`setMode` / `setStyle` / `start` / `pause` …），不读引擎内部状态。
这条窄接口是"引擎纯 TS、界面用框架"能成立的前提。

## 15.0 PWA 交付形态

| 项 | 规定 |
|---|---|
| 安装 | `manifest.webmanifest` + 三档图标（192 / 512 / 512 maskable）+ 竖屏 standalone |
| 离线 | 应用外壳进 precache（约 631KB）；采样走运行时 `CacheFirst`，第一次播到哪首下哪首 |
| 更新 | `registerType: 'prompt'`，**禁止 autoUpdate**——演奏中被强刷是最糟的体验 |
| 版本 | 每次构建产出 `version.json`（`version` / `buildId` / `time`），不进 precache |
| 提示 | 三条信号（SW `needRefresh` / `version.json` 比对 / 手动检查）合成一个开关；演奏中不弹，回首页再出现 |
| 可见性 | 设置页常驻版本号与构建时间，可手动检查更新 |

> 采样不预缓存是有意的：67 个文件 1.42MB，全塞进首装会让"装到桌面"变成一次
> 明显可感的等待；而缺采样时引擎会自动退到合成音色，不会没声音。

## 15.1 场景层（WebGL 视觉系统）

**不做 three.js。** 全屏 fragment shader 提供空间感（透视、体积光、景深），
不含多边形与模型。理由：包体积 20KB vs 600KB、竖屏音符可读性优先、
小程序 `canvas.getContext('webgl')` 可直接跑 GLSL ES 1.00。

### 分层

| 层 | 元素 | 职责 |
|---|---|---|
| L0 | `#glbg` (WebGL) | 场景氛围，30fps 渲染 |
| L1 | `#props` (SVG) | 剪影道具：伏案少女、谱架 |
| L1.5 | `.veil` | 可读性压暗 |
| L2 | `#stage` (Canvas2D) | **透明**，只画轨道/音符/判定线 |
| L3 | DOM | HUD / 面板 |

### 五套场景

| key | 场景 | 光源 | 动态元素 |
|---|---|---|---|
| `cyber` | 赛博朋克 | 霓虹地面自发光 | 透视网格流动、雨丝、扫描线、glitch、屋顶航空灯 |
| `classic` | 音乐家的房间 | 左下壁烛 + 右上月光窗 | 烛焰抖动、木地板反光、飘尘、月光冷斑 |
| `lofi` | 慵懒房间 | 右下台灯 + 窗外冷雨 | 玻璃水珠下滑、雨夜城市、暖雾、窗口冷光柱 |
| `rock` | Live 舞台 | 顶部三束扫射光 | 烟雾、观众剪影（含举手）、频闪、舞台前缘逆光 |
| `pixel` | 像素世界 | 落日 + 透视网格 | 64 格粗采样 + 7 级限色、星空明灭、山脊台阶、CRT 隔行暗带 |

### Uniform 契约（小程序需保持一致）

| uniform | 含义 |
|---|---|
| `uTime` | 秒 |
| `uBeat` / `uBar` | 拍内相位 / 小节数 |
| `uPulse` | 拍脉冲 0–1，每拍置 1 后衰减 |
| `uEnergy` | **命中能量** 0–1.5，每次命中 +0.6/+0.9，按帧衰减 |
| `uDim` | 游戏中压暗 0→1（保证音符可读） |
| `uZone` | 50 连击后的暖推 |
| `uHue` | 和弦色相偏移 |

**关键机制**：`uEnergy` 让"打准"直接点亮场景。这是玩法与视觉的唯一耦合点，
也是"解压"的即时反馈来源——比飘分更有体感。

### 性能约束

- GL 画布按 `0.72 × 屏幕` 渲染再拉伸，全屏 shader 约 28 万像素
- 场景层锁 30fps，游戏层 60fps，二者解耦
- 禁用 `alpha/antialias/depth/stencil`，`powerPreference: 'low-power'`
- WebGL 不可用时回退纯色（`body.no-scene`），玩法不受影响

### 场景与 UI 的联动

切换曲目 = 切换 `body[data-scene]` + 注入 CSS 变量与 Canvas 主题对象：

```
CSS : --accent-a / --accent-b / --accent-rgb / --accent-b-rgb / --accent-glow
JS  : THEME = { a, b, rgbStr, rgbBStr }   // Canvas 侧唯一取色来源
```

**换肤必须是整屏的，不是局部的。** 只改 Logo 和主按钮，玩家感知不到场景变了；
必须连"背景结构"一起换：

| 层 | 跟随换色的元素 |
|---|---|
| 品牌 | Logo 圆标、右上场景胶囊（文字+描边+底色） |
| 结构 | 每个区块标题前的 2px 强调竖条 |
| 选择态 | 模式卡描边与图标、音色卡、难度分段、曲目卡描边与曲名 |
| 入口 | 主按钮渐变与辉光、设置齿轮、开关 |
| HUD | 分数标签、连击辉光、倒计时辉光、结算评级与进度条 |
| Canvas | 判定线、击打区渐变、PAD 轨底、节奏模式的块与敲击区 |

两条硬约束：

1. **颜色只有一处定义**（`SCENES` 表）。CSS 和 Canvas 都从它派生，禁止在绘制代码里写死色值——
   否则会出现"首页是橙色、游戏里判定线还是青色"的割裂。
2. **内容色不跟场景走**：鼓手 4 轨色、旋律家的音名标签是**功能色**（靠颜色区分轨道/音高），
   换肤不得改变它们，否则每首歌都要重新学一遍配色。
   判定线用「白色内核 + 主题辉光」，保证暖色场景下也不会和琥珀色音符糊在一起。

所有换色元素带 `0.3–0.5s` 过渡，切歌时是"渐变"而不是"闪一下"。

**一首歌一套完整配色**，这是"有经验感"的主要来源。

### 首屏取景

首页内容高度随模式变化（节奏模式多一块音色选择），因此「开始演奏」**常驻底部**：
`position: sticky; bottom: 0` + 向上渐隐的深色衬底。

- 内容再长也不会把主行动按钮挤出首屏——这是最关键的一次点击，不能靠滚动才找到。
- 音色选择改为**单行横滑**（一屏露出 4 个半，第 5 个的边角就是"还能滑"的提示），
  纵向只占一行，避免把难度分段挤到按钮下面。

## 16. 小程序实现要点

| 点 | 说明 |
|---|---|
| Canvas | `type="2d"`，按 `dpr` 缩放，`requestAnimationFrame` 驱动 |
| 触摸 | `bindtouchstart/move/end`（多点），不用 pointer 事件 |
| 音频 | `wx.createWebAudioContext`；直接移植 `sfx.ts` 与 `bgm/`（只用 WebAudio 1.0 节点）。`ConvolverNode` 缺失时降级为算法混响 |
| 采样 | 1.42MB：对局 312KB 随主包，BGM 的 1.1MB 按曲目分包；`Int16Array` 解码后缓存，切换曲目不重复解码 |
| 时钟 | **只用一个时钟**：audio context 的 `currentTime`。禁止混用 `Date.now()` |
| 延迟 | 首次进入做一次"听 click 敲屏"校准（8 次取均值），存本地 |
| 包体积 | 主包 1 首，其余分包下载 |
| **音量** | 小程序限制 iOS 无法程序化调系统音量，音量滑块只能用总线 `gain` 实现（已在 `SFX.setMute` 旁预留） |

| 小节格子是否真的建立了"小节感" | 打一局后问："刚才那一小节里有几个音？"答对 = 格子生效 |
| 时值判定后置是否够用 | 入门档打 3 局（只判落点）再进挑战档，看是否需要额外过渡 |
| 一屏 2 个小节够不够预读 | 对比 1.5 / 2.15 / 3 个小节的读谱余裕与压迫感 |
