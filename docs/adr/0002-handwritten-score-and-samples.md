# ADR 0002 · 手写编曲、本地采样、引擎全面 TS 化

- 状态：已采纳（部分取代 [ADR 0001](0001-monorepo-and-framework.md) 的第 3 条）
- 日期：2026-10-24
- 相关：`docs/prd.md` §10 / §12.1、`docs/tech.md` §6、`apps/pwa/src/engine/`

## 背景

v1.5 的产品是可玩的，但音乐不对：

1. **六首曲子听着像同一首。** 旋律全部由「和弦音 + 种子挑动机」生成，结果每首都是
   「每小节六个等距音」——没有动机、没有留白、没有句尾，听十秒就分不清是哪首。
2. **音色有塑料味。** 六个声部共用一张 `VOICE` 表，差别只是方波换锯齿；那个"冲脸的 synth"
   就是原来的方波主音。8bit 味不是风格，是缺点的副产品。
3. **风格与听感对不上。** 摇滚和两首电子用的是同一套音色，月下圆舞不古典，长呼吸不 lofi。
4. **`bgm.js` 是个例外。** 引擎里只有它是运行时生成的，改一次要在七百行里翻；
   而同一份旋律还要被 `game.ts` 读去当谱面（像素心跳），两边命名已经开始漂移
   （`mel` vs `lead`，迁 TS 时才暴露出来，谱面直接抛错）。
5. **采样不能走 CDN。** 离线是 PWA 的卖点，也是小程序的硬约束。

## 决策

1. **旋律手写。** 每首曲子一份数据，一小节一行、16 格（3/4 为 12 格）、`.` 是留白、
   数字是绝对 MIDI。生成器只保留为「没有手写编曲时的兜底」。
2. **音色用真实采样，且全部本地。** 电贝斯 / 电吉他 / 尼龙弦 / 小提琴 / 大提琴 / 长笛 /
   钢琴共 47 个采样（CC0，来自 `tonejs-instruments` 打包的 VSCO2 CE / Iowa / Karoryfer），
   转成单声道 44.1kHz 96kbps 后放 `public/assets/inst/`，随构建发布。
3. **BGM 独立成模块 + 独立音频上下文。** `bgm/` 拆成 9 个文件，单向依赖
   （`compose → score → arrange → voices / samples / drums`，`engine` 只管时钟与状态），
   并拥有自己的 `AudioContext`。
4. **引擎全面 TypeScript 化。** `sfx` / `scene` / `backing` / `game` 四份 `.js` 迁成 `.ts`，
   删除挂在 `window` 上的 IIFE，改为显式 import；`allowJs` 保留但引擎不再有新 JS。

## 为什么手写，而不是把生成器调好

生成器能保证"和弦内、不刺耳、不重复"，但保证不了**有记忆点**。记忆点来自：

| 手段 | 生成器 | 手写 |
|---|---|---|
| 动机重复与变形（同一句换个尾巴） | 做不到，每小节独立采样 | 一行行写，能故意留一个音不弹 |
| 留白（句尾空半小节） | 密度是参数，不会"少写" | `.` 就是留白 |
| 弱起 / 切分落点 | 只能落在预设网格 | 任意格 |
| 情绪走向（八小节一句） | 靠随机 | 第 5–6 行抬高，第 8 行落回主音 |

代价是：**加一首曲子要写数据，不能调参数。** 但七首的量级下，这个成本远低于
"每首都要听十遍才知道像不像"的调试成本。

## 为什么采样要本地，为什么是这些乐器

- 本地：离线可玩；小程序包体可控；不受第三方 CDN 可用性与跨域策略影响。
- 体积：67 个文件 1.42MB，其中 BGM 的六件乐器 1.1MB。不塞进首装 precache，
  走运行时 `CacheFirst`——第一次播到哪首才下哪首，缺采样自动退到合成音色。
- 只留 6–9 个锚点：相邻采样最多差 3 个半音，`playbackRate` 变速再远就会听出"磁带跑调"。
  这也是为什么加音域要补采样，而不是扩大变速范围。

## 为什么引擎这次肯迁 TS

ADR 0001 的判断（"逐行重写成 TS 的回归风险超过收益"）在当时成立，但两个条件变了：

1. **边界已经稳了。** 快照协议定下来之后，`game.js` 的输入输出都是已知结构，
   类型化不再需要边写边改设计。
2. **一次真实事故。** `score.ts` 把旋律字段叫 `lead`，`game.js` 读的是 `mel`，
   `checkJs: false` 让这个错误一路漏到运行时，像素心跳的谱面直接抛异常。
   类型检查能在编译期抓住这一类问题，而这正是引擎最贵的那类 bug（只有玩到那首歌才发现）。

迁移方式仍是**机械迁移**：不改数值、不改时序、不改算法，只加注解与 import 接线。
验证手段是「数值字面量分布对比 + 三模式无头冒烟」，不是"看起来一样"。

## 影响

- 改一首曲子只动 `bgm/compose.ts` 一行；改编曲性格（鼓型、切分）动 `backing.ts` 的 `GROOVE`；
  改听感的空间与总线动 `sfx.ts` 的 `SPACES` / `BUS_DEF`。
- 两套 `AudioContext` 会重复解码 piano（224KB）。已知取舍，见 `tech.md` §11。
- 像素心跳的旋律**同时是 BGM 和谱面**：改那段旋律 = 同时改听感和要打的音。
- 小程序移植时，`sfx.ts` 与 `bgm/` 都要换成 `wx.createWebAudioContext`；
  两者都不碰 DOM，移植面只在"创建上下文"这一处。
